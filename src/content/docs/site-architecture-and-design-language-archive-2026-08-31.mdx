<section id="principles">

## 1) North Star Principles

<div class="dsl-grid dsl-grid--2">
  <article class="dsl-card">
    <h3>Cohesive, not uniform</h3>
    <p>Every section should feel related. No section should feel copy-pasted.</p>
  </article>
  <article class="dsl-card">
    <h3>Scanning first, depth second</h3>
    <p>Indexes optimize orientation. Detail pages optimize comprehension.</p>
  </article>
  <article class="dsl-card">
    <h3>Frame follows content</h3>
    <p>Header strength (`plain` vs `panel`) should match content behavior, not fashion.</p>
  </article>
  <article class="dsl-card">
    <h3>Enhance, never gate</h3>
    <p>Interactive layers are optional. Core reading/navigation always works without them.</p>
  </article>
</div>

<div class="dsl-rulebar" role="note" aria-label="Rule strip">
  <div>
    <p class="dsl-rulebar__label">Bad rule</p>
    <p>One template for every page.</p>
  </div>
  <div>
    <p class="dsl-rulebar__label">Better rule</p>
    <p>One voice, section-specific pacing.</p>
  </div>
  <div>
    <p class="dsl-rulebar__label">Actual rule</p>
    <p>Shared primitives + archetype-aware composition.</p>
  </div>
</div>

</section>

## 3) Foundations

### 3.1 Site topology

```text
/                        switchboard
/notebook                editorial index
/projects                build index
/tools                   utility index
/docs                    manual index
/education               teaching index
/astrophotography        image-led index
/poetry                  literary archive
/tags/[tag]              cross-collection relationship index
```

### 3.2 Foundation stack

<div class="dsl-grid dsl-grid--3">
  <article class="dsl-card">
    <h3>Type and voice</h3>
    <ul>
      <li>technical but human</li>
      <li>concise metadata, generous prose</li>
      <li>clear heading hierarchy</li>
    </ul>
  </article>
  <article class="dsl-card">
    <h3>Surface language</h3>
    <ul>
      <li><code>panel</code> and <code>panel--soft</code> as primary grouping surfaces</li>
      <li>borders carry structure; shadows are secondary</li>
      <li>gradients used to signal section character</li>
    </ul>
  </article>
  <article class="dsl-card">
    <h3>Interaction model</h3>
    <ul>
      <li>link-first navigation baseline</li>
      <li>optional query drawers for power users</li>
      <li>keyboard and focus contracts are mandatory</li>
    </ul>
  </article>
</div>

### 3.3 Theme contract

| Rule | Current behavior | Why |
| --- | --- | --- |
| Global default | Light-first with toggle | broad readability baseline |
| Persisted choice | stored in `localStorage` | continuity across visits |
| Astrophotography exception | forced dark mode | image contrast and section intent |
| System preference fallback | used when no explicit selection | user-respectful default |

### 3.4 Header decision matrix

| Context | Use | Expected result |
| --- | --- | --- |
| text-first longform | `headerStyle: plain` | reduced chrome, reading priority |
| artifact/build/demo lead | `headerStyle: panel` | stronger metadata + media framing |
| panel without hero media | panel text-only fallback | stable visual rhythm |
| education clarity-sensitive page | plain or low-noise panel | cognitive load control |

<section id="diagrams">

## 3.5 Architecture Diagrams

### System path map

```text
Home (/)
  -> section indexes
      -> /notebook
      -> /projects
      -> /tools
      -> /docs
      -> /education
      -> /astrophotography
      -> /poetry
  -> detail pages ([slug] routes)
  -> relationship layer (/tags/[tag])
```

### Interaction stack

```text
[L3] Optional query layer     edge drawers + CLI shell
[L2] Enhanced browse layer    sorting + related tags + quick panels
[L1] Core navigation layer    links + lists + heading hierarchy
[L0] Content baseline         semantic HTML + readable prose
```

### Theme resolution flow

```text
Route = /astrophotography ?  yes -> force dark mode
                              no -> check saved theme
                                         -> if missing, use system preference
```

  <span><strong>L0-L3</strong>: layered interaction model</span>
  <span><strong>force dark mode</strong>: route-level exception, not user toggle failure</span>
</div>

<section id="patterns">

## 5) Shared Pattern Library (Operational)

### 5.1 Reuse-first primitives

| Primitive | Intent | Anti-pattern |
| --- | --- | --- |
| `Header` | global orientation, route access, theme control | per-section nav forks with divergent behavior |
| `IndexHeader` | section identity + status framing | bespoke hero wrappers per index |
| `panel` / `panel--soft` | content grouping and visual rhythm | custom one-off card wrappers |
| `pill` / `pill--link` | compact metadata and taxonomy | ad-hoc tag styling across sections |
| `edge-drawer-*` | optional side-utilities | modal-only query tools that block reading |
| `CliShell` | command-style discovery for dense indexes | shell UX without link-based fallback |

### 5.2 Drawer pattern contract

<div class="dsl-grid dsl-grid--2">
  <article class="dsl-card">
    <h3>Do</h3>
    <ul>
      <li>keep drawer optional</li>
      <li>include close/backdrop affordances</li>
      <li>hide query overlays on constrained mobile breakpoints</li>
      <li>keep equivalent content discoverable through page structure</li>
    </ul>
  </article>
  <article class="dsl-card">
    <h3>Do not</h3>
    <ul>
      <li>hide critical navigation inside drawers</li>
      <li>require shell commands for core discovery</li>
      <li>ship keyboard-inaccessible overlays</li>
      <li>duplicate taxonomy logic between drawer and page with mismatch</li>
    </ul>
  </article>
</div>

### 5.3 Metadata and taxonomy contract

- Tags must be meaningful across collections, not collection-local aliases.
- `featured` marks editorial priority, not simply recency.
- Date signals should consistently resolve from `updatedDate` then `pubDate` where applicable.
- Taxonomy pills in education should map to tag routes only when actual tag data exists.

</section>

## 5.5 Component Anatomy

<div class="dsl-anatomy">
  <article class="dsl-anatomyCard">
    <h3>Global Header Anatomy</h3>
    <ol>
      <li><strong>Brand anchor:</strong> stable home return point.</li>
      <li><strong>Primary route rail:</strong> section-level navigation.</li>
      <li><strong>Theme control:</strong> explicit user preference override.</li>
      <li><strong>Utility link:</strong> source / external utility access.</li>
      <li><strong>Sticky frame:</strong> persistent orientation while scrolling.</li>
    </ol>
  </article>

  <article class="dsl-anatomyCard">
    <h3>Index Card Anatomy</h3>
    <ol>
      <li><strong>Kicker/meta:</strong> type, featured state, date.</li>
      <li><strong>Primary title:</strong> strongest click target.</li>
      <li><strong>Description:</strong> one-paragraph scan summary.</li>
      <li><strong>Tag row:</strong> relationship routing to related content.</li>
      <li><strong>Media slot:</strong> optional visual context, never required for function.</li>
    </ol>
  </article>

  <article class="dsl-anatomyCard">
    <h3>Edge Drawer Anatomy</h3>
    <ol>
      <li><strong>Tab handle:</strong> discoverable but low-noise trigger.</li>
      <li><strong>Backdrop:</strong> explicit close affordance.</li>
      <li><strong>Panel shell:</strong> isolated utility context.</li>
      <li><strong>Query engine:</strong> filter/open behavior on indexed content.</li>
      <li><strong>Manual layer:</strong> command help without leaving current page.</li>
    </ol>
  </article>

## 6) Accessibility and Quality Gates

<table class="dsl-checklist">
  <thead>
    <tr>
      <th>Gate</th>
      <th>Minimum requirement</th>
      <th>Ship decision</th>
    </tr>
  </thead>
  <tbody>
    <tr>
      <td>Semantic structure</td>
      <td>single `h1`, logical heading tree, landmark clarity</td>
      <td>block if violated</td>
    </tr>
    <tr>
      <td>Keyboard flow</td>
      <td>all interactive controls reachable and operable by keyboard</td>
      <td>block if violated</td>
    </tr>
    <tr>
      <td>Focus visibility</td>
      <td>focus indicator visible against all surfaces</td>
      <td>block if violated</td>
    </tr>
    <tr>
      <td>Color semantics</td>
      <td>state/meaning not encoded by color alone</td>
      <td>block if violated</td>
    </tr>
    <tr>
      <td>No-JS resilience</td>
      <td>core browse/read path still works without client scripts</td>
      <td>block if violated</td>
    </tr>
    <tr>
      <td>Responsive integrity</td>
      <td>no clipped content or unusable controls at narrow viewport widths</td>
      <td>block if violated</td>
    </tr>
  </tbody>
</table>

### 6.1 Pre-merge design QA

1. Archetype identified and respected.
2. Existing primitive reused where possible.
3. Theme behavior verified on both light and dark modes.
4. Route-specific theme exceptions verified (astrophotography).
5. Keyboard and screen-reader basic pass completed.
6. Mobile breakpoint pass completed.
7. Spec updated if behavior changed materially.

</section>
