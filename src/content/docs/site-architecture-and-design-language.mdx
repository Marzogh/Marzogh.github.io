  <div class="design-manifesto__copy">
    <p class="design-kicker">Working System</p>
    <h2 class="design-manifesto__line">
      One site, several modes, one visual grammar.
    </h2>
    <p class="design-manifesto__summary">
      Chips'nCode should feel coherent across writing, utilities, documentation, education, projects, and
      astrophotography without forcing them into one generic shell. The design language needs to hold the whole site
      together while still letting each section behave like the thing it actually is.
    </p>

<section id="headers">

## Header modes

<div class="design-headerModes">
  <div class="design-headerModes__spec">
    <span class="design-headerModes__mode">headerStyle: plain</span>
    <div class="design-headerModes__wire design-headerModes__wire--plain"></div>
    <p>Use when the page wants title-first reading, less chrome, and a quieter technical tone.</p>
  </div>
  <div class="design-headerModes__spec">
    <span class="design-headerModes__mode">headerStyle: panel</span>
    <div class="design-headerModes__wire design-headerModes__wire--panel"></div>
    <p>Use when the page benefits from framed metadata, early media, or a stronger artifact-led opening.</p>
  </div>
</div>

<p class="design-note">
  Plain is not automatically better. It is simply better for some kinds of content. Showcase-style material can still
  need a stronger frame.
</p>

<section id="rules">

## Current rules

<div class="design-ledger">
  <div>
    <p class="design-kicker">Do</p>
    <ul class="design-list">
      <li>let layouts react to the content, not just the viewport</li>
      <li>use text-first variants when entries have no media</li>
      <li>treat indexes as editorial surfaces rather than uniform grids</li>
      <li>choose <code>headerStyle</code> on editorial grounds</li>
      <li>keep image-led sections image-led</li>
    </ul>
  </div>
  <div>
    <p class="design-kicker">Do not</p>
    <ul class="design-list">
      <li>force every section into the same post shell</li>
      <li>replace one repetitive card system with another repetitive card system</li>
      <li>add terminal styling where it serves no purpose</li>
      <li>assume plain headers are universally better</li>
      <li>change astrophotography casually because another section changed well</li>
    </ul>
  </div>
</div>

</section>

## Practical authoring note

If a new entry is mostly writing, reference, or explanation, start with:

```yaml
headerStyle: plain
```

If it is mostly artifact, media, or structured showcase material, start with:

```yaml
headerStyle: panel
```

Then let the page argue its case.
